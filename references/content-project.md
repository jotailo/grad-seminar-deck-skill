# 项目进展汇报：逐页内容清单

组会上的「项目」指的是**有立项或合同、有节点、有人要跟你对账**的活，只有两类：

| 类型 | 典型来源 | 「进度」拿什么对账 | 「卡点」通常在哪 |
|---|---|---|---|
| **A 科研项目** | 国家/省/校基金、重点研发子课题、企业横向课题、导师主持的课题 | 任务书节点、结题指标（论文/专利/软著/数据集/样机）、实验批次 | 数据拿不到或标注不完、算力不够、方法不收敛、合作单位数据未到、中期检查材料 |
| **B 外包 / 委托项目** | 老师接的企业或事业单位开发、算法、系统集成委托 | 合同里程碑、交付物（需求书/原型/接口/试运行/验收）、版本与上线时间 | 需求变更、甲方接口或数据权限没开、验收标准分歧、现场环境与开发环境不一致 |

**不属于这两类的，不要放进「项目进展」**：读了几篇文献、写了多少字综述、代码 commit 多少——那是个人学习量，属于论文类或实验类的素材。把它当项目汇报，导师第一反应是「这项目到底立没立项」。

2–4 页，默认 3 页。项目汇报讲的是**能不能按时交账**，不是技术方案讲解。

## 第 1 页：名称 + 进度（`image` 或 `cards`，roles: `name`, `progress`）

项目名称要写全到能对上账，一句话交代身份：

```
A 类：国家自然科学基金面上项目「面向长程任务的智能体编排」（6220XXXX，2025.01–2028.12）
　　　本人负责子课题 2：编排范式可归因性评测
B 类：XX 市水务集团委托「管网缺陷智能识别系统」（合同 2026.03–2026.12，算法负责人）
```

- **进度必须是可核对的量，不是感觉**：
  - A 类：任务书 4 个节点已完成 2 个；指标「论文 2 篇」已投 1 篇在审、1 篇在写；数据集已标注 3 200 / 5 000 张
  - B 类：里程碑 M1 需求确认（已签）、M2 原型（已验收）、M3 接口联调（进行中 70%）、M4 试运行（未开始）
- **一张图**：A 类用「节点甘特 + 指标完成度」，B 类用「里程碑状态条 + 交付物清单」。有图先看图，比一段文字有说服力。
- `takeaway` 写一句总体判断，让听众第一句就知道要不要担心：「M3 联调受甲方接口延迟影响，其余按合同推进」。

## 第 2 页：当前遇到的问题（`bullets`，roles: `problem`）

2–3 条，每条三件事：**现象 → 已经试过什么 → 卡在哪**。两类项目的问题写法不一样：

**A 类（科研）**——问题要落在研究本身，不是「比较忙」：

```
卡点一：Loop 编排在步数 >12 后成功率从 71% 掉到 43%，怀疑记忆写入污染了后续决策。
　→ 试过：截断上下文 / 换更小写入阈值，均只缓解不解决；需要设计一组消融定位
```

**B 类（外包）**——问题要落到「谁卡了谁、什么时候要」：

```
卡点二：甲方历史影像库的调阅权限未开通（已邮件催两次，对接人 10-28 承诺本周内）。
　→ 影响：M3 真实数据联调无法开始，只能先用 200 张样例图跑通流程；若 11-05 前未开通，M4 顺延一周
```

- **不要只报喜**。一份不写问题的进度汇报，导师会认为你没在做或没在想。
- 问题要具体到能讨论：「接口返回字段缺失 lat/lon」而不是「对接不顺利」。
- **等外部条件的单独列一条**，写清「等谁、等到什么时候、超期怎么调整」——这是项目汇报里最有价值的一句话，也是唯一能让老师立刻拍板的地方。
- B 类项目**脱敏**：不写合同金额、不写甲方内部系统名与人员全名，用「甲方」「对接人」即可。组会上说漏了，是老师去道歉。

## 第 3 页：下一步（`bullets` 或 `table`，roles: `plan`）

按时间分层，每条给**可验收的产物**，而不是动作：

- A 类：「本周：完成两组消融（步数上限 / 写入阈值），产出定位结论一页纸」「两周内：投稿稿件的实验章节定稿」「节点 3 中期材料 11-20 前交科技处」
- B 类：「本周：样例数据跑通全流程，出联调自测报告 v1」「11-05 前：拿到权限后完成真实数据联调，问题单收敛到 ≤5 条」「11-15：M3 验收演示」

- 需要老师定夺的，单独一条并给选项：「指标 2 篇是否接受 1 篇 SCI + 1 篇顶会」「M4 顺延是否需要先跟甲方口头报备」。
- **B 类不要自己许排期**。写成「建议 M4 顺延一周，待老师与甲方确认」，而不是「我把 M4 改到 12-20」。
- 结尾 `takeaway` 收一句：「卡点都在外部依赖，内部按节点推进」。

4 页版本：第 1 页只放名称 + 进度图；新增一页 `columns` 放「已完成节点 / 交付物 / 风险」（`roles: ["progress"]`）。

## 验收前自己先过一遍

- [ ] 项目名称带了类别、编号或合同期、我的角色——不写这三项，听众不知道你在对谁负责
- [ ] 进度里至少 3 个数字能和任务书/合同或周报对上
- [ ] 问题写了「等谁、等到什么时候、超期怎么办」
- [ ] 下一步每条有验收标准和时间点
- [ ] B 类已脱敏，未替老师承诺排期

## 常见扣分点

- 把个人学习量当项目进展（「文献池 42 篇」），项目本身一句没提。
- 进度全用形容词（「基本完成」「进展顺利」），没有一个可核对的数字。
- 问题写得含糊，导致讨论无法落地。
- 下一步没有时间点，也没有可验收的产物。
- 项目类硬套「实验报告」的结构（写实验目的、结论），两类不要混。
- B 类项目在组会上暴露甲方敏感信息。
