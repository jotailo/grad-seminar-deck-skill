# 实验报告：逐页内容清单

组会上的实验报告不是日志，回答的是三件事：**你想验证什么、结果支持不支持、接下来怎么办**。
2–4 页，默认 3 页。

## 第 1 页：名称 / 目的 / 设置（`cards`，roles: `name`, `purpose`, `setup`）

- **实验名称**：能被检索到的名字，如「长上下文记忆消融（MemAgent-lite）」，不要写「实验一」。
- **实验目的**：一句可证伪的话。「验证 A 是否比 B 好」不够，要写清在什么条件下、用哪个指标。
  反例：「探索记忆模块的作用」。正例：「在固定 token 预算下，判断增益来自更长的上下文还是有选择地写入记忆」。
- **实验设置**：
  - 数据：数据集/子集名称与规模（`LongBench 三个子集，共 1.2k 条`）
  - 基线/对照：至少写清 A/B/C 三组的差别只有一个变量
  - 指标：EM / F1 / 成功率 / 平均步数 / token 消耗，写全
  - 控制变量：同骨干模型、同工具集、同随机种子
- 有预算/时长/算力的硬约束，一并写在设置里（组会上必被问）。

## 第 2 页：核心发现（`image` 或 `table`，roles: `finding`）

- 一张结果图 + 3 条解读。图给「对照」，不要只给最优那条线。
- 每条发现必须是「数值 + 方向 + 解释」：写「同预算下 C 比 A 高 3.8 个点 EM、token 少 22%」，
  不写「C 表现更好」。
- 有异常就说异常：「B 在长文档上崩得比预期快，疑似截断丢掉关键定义」。异常往往比主结果有价值。
- `caption` 写明「图几　画的是什么（自绘 / 数据见实验记录编号）」。

## 第 3 页：局限 / 后续 / 结论（`columns`，roles: `limit`, `next`, `conclusion`）

三栏，每栏 2–3 条，短句：

| 栏 | 写什么 | 不要写 |
|---|---|---|
| 局限 | 具体的：只跑了 3 个子集 / 阈值手调 / 单人判定无一致性检验 | 「时间有限」「还需深入」 |
| 后续可做 | 可执行、有先后的：补 2 个子集 / 阈值做成可学习参数 | 「继续优化」 |
| 结论 | 一句能被引用的话：支持了什么、不支持什么 | 「实验取得成功」 |

结论要敢下边界：「记忆写入在预算受限时有稳定收益，但暂不能推广到短文本任务」。

## 4 页版本怎么排

第 2 页拆成两页：② 主结果图（`finding`）③ 消融/对照表（`table`，`finding`）。
对照表列：`设置 | 指标1 | 指标2 | 结论`，把「哪个改动带来哪个变化」写进最后一列。

## 常见扣分点

- 目的写成「验证方法有效性」——不可证伪，等于没目的。
- 只有主结果，没有对照；或三组设置之间差了两个以上变量（讲不清是谁的功劳）。
- 图是截图但坐标轴数字看不清（截图 dpi 不够，见 `figure-capture.md`）。
- 局限一栏全是套话，导师一问就答不上来。
- 结论与数据方向相反（如数据是「持平」，结论写「显著提升」）。交付前把每个数字对回实验记录。
