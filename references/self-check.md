# 自检：四关，逐项打勾

机器能查的交给脚本，机器查不出的（不好看、讲不通）必须看图。**任何一关有 FAIL 都不算交付完成。**

## 第一关 结构（`check_structure.py`）

```bash
python scripts/check_structure.py deck.json
```
→ 打印每个单元的内容点、页数、证据图、汇总表核对结果；退出码 0 表示可进下一关。

逐项确认：
- [ ] 每种汇报的必备内容点齐全（论文 9 项 / 实验 7 项 / 项目 4 项）
- [ ] 每个单元 2–4 页
- [ ] 多篇论文时有汇总表，且列齐（标题/出处/发布时间/一句话）、行数 = 篇数
- [ ] 每个单元至少一张图；论文的图来自原文
- [ ] 论文出处页写了期刊/会议等级口径，或明确写「未核实」
- [ ] `mapping` 用的是表格，不是一段话
- [ ] 项目的「进度」有三个以上能对上任务书/合同的数字，不是「进展顺利」这类形容词
- [ ] 委托/外包项目已脱敏（无合同金额、无甲方内部系统名与人员全名），且没有替老师承诺排期

## 第二关 版面（`check_deck.py`）

```bash
python scripts/check_deck.py 组会汇报.pptx
```
→ 查溢出、字号、越界、遮挡、插图 dpi、空页；输出字号分布便于核对层级。

逐项确认：
- [ ] 零 FAIL
- [ ] 正文字号 ≥14pt，任何文字 ≥10pt（`[字号分布]` 里最小那档不是正文）
- [ ] 插图 dpi ≥150（≥110 是底线，<110 必须重裁）
- [ ] 表格没报「文字溢出」
- [ ] 没有「疑似遮挡」

## 第三关 目检（必做，不能跳）

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/render_deck.ps1 -Pptx "组会汇报.pptx"
```
→ 在 `render/` 下逐页导出 PNG。然后**一张一张看**，每页问四个问题：

- [ ] **遮挡**：有没有文字压到图、表、色块上？结论条有没有盖住最后一行？
- [ ] **裁切**：每张截图是否完整（图注在、坐标轴在、表格最后一行在）？
- [ ] **字号**：坐后排能不能看清？尤其表格单元格和图注。
- [ ] **对齐与留白**：标题左边缘是否一条线？有没有整页只有两行字的空页？

再看三个全局项：
- [ ] 分区页、目录、页码能对上（目录说 3 类，就真的 3 类）
- [ ] 每页角标（`论文阅读汇报 · 2/3`）与所在位置一致
- [ ] 结束页之后没有多余空白页

没有 PowerPoint 就人工打开逐页看，并在交付时写明「未做渲染目检」——不要假装看过。

## 第四关 事实（人工，最容易被跳过）

做一张核对表，把 PPT 上出现的每一个可核查项对回原始出处：

| 类型 | 核对什么 | 出错后果 |
|---|---|---|
| 数字 | 准确率、提升幅度、样本量、token 数 | 导师一问就崩 |
| 名字 | 作者、方法名、数据集名、基线名 | 拼错显得没读原文 |
| 等级 | CCF / 中科院分区 / JCR / 顶会 | 说错等于学术判断不可信 |
| 页码 | 页脚 `source` 与截图实际页码 | 现场翻不回去 |
| 方向 | 结论是「提升」还是「持平」，有没有夸大 | 与数据矛盾，最严重 |

- [ ] 每个数字都能在原文/实验记录里指到具体位置
- [ ] 没有「显著提升」而数据只是持平
- [ ] 页码范围与截图一致（改过图就重对一次）

- [ ] 说明所用默认（语言、时长）与未解决项（未核实的等级、缺原文图表的论文）
